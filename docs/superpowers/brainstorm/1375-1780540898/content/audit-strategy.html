"双重审查"还是"一次写完"?

CharacterArc 的核心保险机制是:章节生成完后,自动用另一个 LLM 调用做 chapter-audit(检查 OOC、伏笔失管、设定冲突),发现问题再触发 chapter-repair。

这是质量上很重要的一道闸,但代价是每章 token 大约翻倍。你怎么看?

A

愿意,质量优先(推荐)

策略:写完一章 → 后台自动跑 audit → 有问题就显示警告 → 你点修复或忽略

代价:每章 token ≈ 1.5-2x。但 audit 可以用便宜模型(比如 Haiku 审 Sonnet 写的)

你 A 痛点的核心解药:OOC 和"AI 味重"基本就是靠这道闸抓的

B

愿意,但只在弧/卷边界审(像 ainovel-cli)

策略:每章不审,跑到一弧结束(5-10 章)做一次集中评审,问题章节进入 PendingRewrites

代价:省 token,但问题晚发现,弧末重写多章很重

适合:你写得快、不在意中间几章质量,等弧末统一打磨

C

不要自动审,我自己判断

策略:AI 只负责写,质量由你审稿。系统提供工具(选中段落问"这段有什么问题")让你按需调用

代价:省 token 最多,但这会把你的"A 痛点"原样保留 —— 你说过"受不了写得质量一般",所以这选项跟你需求冲突

适合:重度审稿型用户,有耐心精读每章

D

双轨:章末轻审 + 弧末重审

策略:每章后用便宜模型做轻量 OOC/AI 味检测(快,token 少);弧末再用强模型做完整 7 维评审

代价:总 token 比 A 略高,但分摊到每章后台跑感知不到

这是从 ainovel-cli 和 CharacterArc 各取一半的混合方案
