你想在哪里写?

这决定了用什么技术栈、能不能离线用、能不能放在多设备同步。一旦选了很难改。

A

桌面 GUI 应用(像 CharacterArc)

形态:Electron / Tauri 打包的桌面应用,双击运行

编辑器:富文本(TipTap / ProseMirror),所见即所得,中文排版自动正确

数据:本地 SQLite

API key:存本机配置,不出门

优点:体验最好,富文本天然适合长文 / 缺点:技术栈复杂(前端 + 主进程 + IPC),开发慢

B

本地 Web 应用(浏览器打开 localhost)

形态:跑一个本地 server,你用浏览器访问 localhost:xxxx

编辑器:同样富文本,但跑在浏览器里

数据:本地 SQLite 或 JSON 文件

优点:同样的代码以后想部署到云上、想多端同步都简单很多 / 跨平台天然 / 缺点:每次要先启 server,体验稍逊桌面应用

C

TUI(终端界面,像 ainovel-cli)

形态:命令行启动,在终端里跑全屏 TUI

编辑器:有限富文本,基本是纯文本编辑

优点:开发最快,可以 SSH 远程用,极客友好 / 缺点:中文排版/段落感受/光标体验都比 GUI 差,长篇审稿不舒服

D

VS Code / Obsidian 插件

形态:把编辑器外包给已有工具,你只写"AI 大脑"那部分

数据:Markdown 文件(在 VS Code / Obsidian 工作区)

优点:省一半开发量,你已有的写作工作流不变 / 缺点:UI 受限于宿主,做"双粒度"的内嵌交互比较别扭
