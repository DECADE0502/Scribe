## Read This First

This repository is **Scribe**, a local-first AI long-form novel writing workspace.

The user cares most about reader-visible long-form writing quality: continuity, reusable memory, SillyTavern-compatible prompts/worldbooks, editable story state, and a workflow where the author can inspect and control chapter output before the system records new durable memory.

Do not reduce the project to "tests pass" or "imports work". The acceptance bar is that imported settings, worldbook entries, prompt presets, audit findings, hard facts, and structured memory all affect later writing in a stable way.

## Core Mental Model

Scribe is a writing-quality control loop:

```text
book settings / outline / characters / rules / imported presets / worldbook
  -> context builder
  -> chapter generation
  -> chapter file + version saved
  -> audit
  -> hard-fact quality gate
  -> optional repair
  -> state recording
  -> structured memory, timeline, foreshadowing, generic records, reader issues
  -> next chapter context
```

The important separation:

1. Writing call creates prose.
2. Audit call reviews prose and extracts quality/continuity information.
3. State-recording call updates durable memory only after final prose is accepted.

This separation is intentional. The danger is recording state from a bad chapter. The current architecture therefore tries to run hard-fact checks before `recordChapterState()`.

## Main Product Work Currently In Tree

### 1. Generic hard-fact continuity gate

The project is moving away from book-specific checks such as pet-capture vocabulary. The intended shape is generic:

- Extract prior facts from structured character state, generic records, summaries, timeline, active foreshadowing, and relevant context.
- Extract current claims from audit output and deterministic text scanning.
- Compare prior facts with current claims.
- Repair contradictions when possible.
- Do not record durable memory if unresolved hard-fact contradictions remain.

## Known Remaining Risks

### 1. Encoding display is messy in PowerShell output

Several Chinese docs/source comments display as mojibake in `Get-Content` under the current terminal settings. Git diff may still show readable text depending on encoding path. If editing Chinese text, confirm the actual file encoding and avoid accidental corruption.

### 2. Hard-fact gate first-chapter blind spot

If chapter 1 invents a wrong value and there are no prior durable facts, the hard-fact gate may not catch it. A possible next improvement is a "setting-vs-chapter" check that extracts hard facts from premise/meta/outline/user intent and compares them against chapter 1.

### 3. Deterministic extraction can miss implicit changes

If prose avoids explicit numbers or status values, deterministic extraction may not catch contradictions. The gate works best when the chapter states values clearly or audit hardFacts are populated well.

### 4. Audit may be too permissive

Earlier live runs saw audit return `ok` even when required status content was missing. Continue treating deterministic required-section checks and hard-fact gates as first-class, not merely advisory.

## What Not To Do

- Do not hardcode terms for one demo book or genre.
- Do not let bad chapters update durable memory.
- Do not expose full generated prose in left-side conversation deltas.
- Do not assume a green TypeScript run proves writing quality.
- Do not delete or reset unrelated dirty files.
- Do not commit secrets from `%APPDATA%\scribe\secrets.env`, local runtime DBs, or unrelated private exports.
